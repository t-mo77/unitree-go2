日付：2026-11-11。親の設計書は `docs/design.md` と、物の最初の一歩の [`2026-11-05-go2-objects-design.md`](2026-11-05-go2-objects-design.md)（以下「物の設計書」。ここに書かないことは、そちらに従う）。
調べた記録：メインのチェックアウトの `.superpowers/sdd/2026-11-11-go2-open-objects/`（git に入っていない）。`decisions.md`（controller の判断 D1〜D11）、`code-map.md`（box・chair が書いてある所、流れ、上限、プロンプトの大きさ、テスト）、4 つの部分の設計（`design-near.md`・`design-vocabulary.md`・`design-language.md`・`design-detector.md`）、単語帳の下書き `vocabulary.draft.json`、試し（`spike/`）。

**【仮】の印：** 試し（spike）の数は、共有の Mac で 1〜3 回ずつ測った値で、これから測り直す。この設計書では【仮】と書く。カメラの試し（`spike/gazebo-camera.md`）は書き終わり、controller が D7 の判断を出した（§5）。検出器の試し（`spike/detector.md`）は、試しの部屋の絵での数で、この設計書の部屋（§12）では測っていない。

## 1. 何を作るのか・なぜ

「箱の周りを一周して」「椅子まで歩いて」は動くようになった（物の設計書 §2）。でも物の種類は箱と椅子の 2 つだけで、コードに書いてある。利用者は「なぜ種類を 1 つずつ足さないといけないのか。共通のラベル表と、名前で探せる認識器（open-vocabulary）を使えないのか」と聞いた。

**今、1 つずつ足すしかないわけ。**
- box と chair が、コードの十数か所に書いてある（code-map §2）。`objects.py` の `LABEL_JA`・`LABEL_WORDS`・`ID_RE`・`PROP_RE`・`DEFAULT_SIZE`・`DEFAULT_LAYOUT`、Gazebo の `object_sdf`・`OBJECT_SPAWN_Z`、画面の色、`objects_check.py` のしきい値、言い方の試験の場面など。ほかの名前の物が来ると `LABEL_JA[label]` で止まる。
- 「検出器の文字がプロンプトに入らない」（R21）を、コードに書いた 2 つの名前だけを通すことで守っている。
- 大きい家具（テーブル・ソファ）には、今の「手前のマス」の決まりで手前のマスが 1 つもない（中心から測る帯が、半径 0.55 m を超える物で空になる。code-map §4）。種類を足しても「ソファまで歩いて」はできない。

**答え。**
- **種類をデータにする（共通の一歩）。** 種類の一覧、日本語の名前と言い方、検出器に渡す英語、ふつうの大きさと高さを `voice_ltl/vocabulary.json` に置く。コードはそれを読むだけにする。種類を足すのは、このファイルを直してテストを通すことで、コードは変えない。R21 は「このファイルにある名前だけを通す」で守る。
- **共通のラベル表は元にするが、そのままは入れない。** v1 は COCO・LVIS・Objects365 から、家の中で床に置く物を 47 種類選ぶ。全部を入れないわけ：
  - 日本語の言い方は、種類ごとに人が確かめる必要がある。「本」は「1本」の数え方で、「日本」の終わりにもある。「ゴミ箱」は「箱」を含む。
  - 行き先にならない物が多い。机の上の物（LiDAR には下の机しか見えない）、床に平らな物、家の作り（ドア・階段）、生き物（動く。D1）。
  - 計画には、LiDAR が測るまでの種類ごとのふつうの大きさが要る。
  - プロンプトには入りきらない（LVIS の 1203 種類なら、プロンプトが倍の長さになる。code-map §5）。入れる必要もない。言い方はコードが単語帳で引き、Claude の答えは単語帳で確かめる（§9）。
- **名前で探せる認識器は、同じファイルの英語で動く（A）。** YOLOE の文字プロンプトに、単語帳の `detect` の英語を渡す。種類を足せば、検出器が探す物も増える。イメージは作り直さない（§11.1）。
- **大きい物の「手前」を、物の縁から測る決まりに直す（D6）。** 箱と椅子のマスは今と同じに保つ（§10）。

利用者は「共通の一歩、それから A」を選び、質問なしですぐ始めるように言った（decisions.md）。

## 2. ゴール

**共通の一歩（S）**
1. 物の種類は `voice_ltl/vocabulary.json` で決まる。種類や言い方を足すのに、コードは変えない（ファイルを直して、読み込みのテストを通す）。
2. v1 の単語帳は、家の中の 47 種類（箱と椅子を含む。生き物は入れない。§7.4）。
3. 物の一覧にある物なら、どの種類でも「〈物〉まで歩いて」「〈物〉の周りを回って」が式になり、Go2 がそのとおり動く。単語帳にある種類が一覧にない・2 つ以上あって決められない・遠すぎる、のときは、本当の理由で断る（§9.6）。
4. 「手前」は 2 m ほどの物（テーブル・ソファ）にもある（D6）。周回は今までどおり、対角 3.5 m 未満の物まで（§10）。
5. 今までの指示（物を使わない指示）の振る舞いと速さ、既定の置き方（box_1・chair_1）の PLANT、物の設計書 §2 の箱と椅子の数は変わらない。

**A（Gazebo で、描いたカメラの絵から物を見つける）**
6. Gazebo の Go2 が、前のカメラの絵（YOLOE）と LiDAR から物を見つけ、今と同じ形の `/go2/objects` を出す（`OBJECTS_SOURCE=detector`）。
7. 論理カメラ（logical camera）は、どちらの切り替えでも正解（ground truth）として残り、検出の正しさを測れる。`OBJECTS_SOURCE=logical`（既定）の Gazebo は今と同じ（ロボットの記述と ros_gz_bridge の引数がバイト単位で同じ）。
8. 検出器は取り替えられる。ultralytics は検出器のイメージと 1 ファイル（`detector/yoloe.py`）にだけあり、app のイメージには入らない（D5）。

合格の条件の数は §13。

## 3. やらないこと

- 実機（B）。実機への窓口は物の設計書 §11 のまま（同じ `/go2/objects`）。
- 動く物・人・動物を行き先にすること（D1）。生き物は LiDAR の障害物のまま。検出器は見つけても捨てる（`detect_ignore`）。
- マス目の上限（256 マス）に入らない大きさの物の周回。その物は新しいメッセージで断る（§10.6）。
- 足跡（上から見た四角）より細かい形。高さや 3D の形、物の向き（yaw）は送らない（O13）。
- 色や形の言葉（「赤い椅子」）、「あれ」「それ」、物を押す・持つ、物を探して見回すこと。
- 種類ごとの絵（アイコン）や色（§9.7）。
- 検出器の状態を画面に出すこと（O23。記録と `objects_check.py` だけ）。
- リポジトリに LICENSE ファイルを足すかどうか（利用者の別の判断。D5）。
- main への取り込み（D10）。

## 4. 失敗とみなすこと

- 単語帳にない種類が、どこかから通る（Claude の答え、検出器、配置ファイル、Gazebo のモデル名）。検出器の文字や Claude の書いた英語が、プロンプト・画面・メッセージに出る（出てよいのは、単語帳の `ja` と、利用者の言葉に合った単語帳の言葉だけ。O3）。
- 物のマスに入る計画、物にぶつかる計画が出る。足跡が本当の物より小さく送られる（§10.9）。
- 既定の置き方の World（PLANT の状態・遷移・ラベル）が変わる。§2 の箱と椅子の数が満たせなくなる。物を使わない指示の振る舞い・速さが変わる。
- 種類を足すのに、コードを変える必要がある。
- app のイメージに torch・ultralytics が入る。`detector/yoloe.py` のほかで ultralytics か torch を import する。
- `OBJECTS_SOURCE=logical` の Gazebo が変わる（カメラが描かれる、引数が変わる）。`/go2/objects` を 2 つが同時に出す。
- 検出器が、見落としただけで本当の物を忘れ、番号を付け直す。生き物を行き先として出す。
- Gazebo の時間の測りを、ほかの重い container と同じ CPU で流す（decisions.md の process lesson）。利用者の Gazebo を止めさせる・待たせる（D11）。

## 6. 全体の流れ

```
voice_ltl/vocabulary.json ──読み込み・確かめ（fail closed）──> objects.py（許可リスト LABELS・名前・言い方・大きさ・高さ・検出の言葉）
        │                       app・偽の Go2・gazebo_bridge・検出器が、同じファイルを同じ読み込みで使う
        │
Gazebo（Jazzy、配置ファイル gazebo/layouts/<名前>.json の物を置く）
 論理カメラ ＋ LiDAR ── gazebo_bridge ──┬──> /go2/objects（OBJECTS_SOURCE=logical のときだけ）
                                         └──> /gazebo/objects_truth（いつも。配置ファイルの本当の足跡。正解）
 前のカメラ（detector のときだけ描く）＋ /utlidar/cloud ＋ odometry ── detector（YOLOE、別の container）──> /go2/objects（detector のとき）

app（Humble）：物の一覧 → 指示を受けたときに凍結（Scene）
  → プロンプト（近い 8 個。言われた種類は必ず載せる）→ Claude → 式 / unresolved_objects
  → 確かめ（単語帳と Scene）→ grid_world（足跡で塞ぐ・手前の帯 A＋B・周回の輪）→ 合成 → GridExecutor
```

## 7. 単語帳（`voice_ltl/vocabulary.json`）

### 7.1 置き場所と読み込み

- 置き場所は `voice_ltl/vocabulary.json`。JSON にするのは、`objects.py` を標準ライブラリだけに保つため（Jazzy の `gazebo_bridge` も検出器も import する）。
- `objects.py`（または `objects.py` が import する標準ライブラリだけの小さい部品）が import のときに 1 回読む。§7.3 の決まりに 1 つでも合わなければ例外を出し、app・橋渡し・検出器は起動しない（fail closed）。
- 読み込みが渡すもの：許可リスト `LABELS`、label → 名前（`ja`）、言い方、ふつうの大きさと高さ、検出の言葉 → label の表、`DETECT_IGNORE`、Claude の英語の別名 → label の表（§9.4）。
- JSON Schema（`voice_ltl/vocabulary.schema.json`）は説明とテストのためだけに置く。読み込みは jsonschema を使わず、§7.3 を自分で確かめる。形は `design-vocabulary.md` §3.1 のもの（`en` を足し、`height` を必須にする。O4）。

### 7.2 項目

上の段：`version`（1）、`labels`（2〜200 個）、`not_words`（任意）、`detect_ignore`（任意）。種類ごと：

| 項目 | 要る | 意味 |
|---|---|---|
| `label` | 必須 | D2 の形の英語の名前。すべての行・Gazebo のモデル名・Claude の答えを通す許可リスト |
| `ja` | 必須 | 画面・メッセージ・プロンプトに出す名前（例：ゴミ箱）。言い方（`words`）の 1 つ |
| `words` | 必須（1〜20） | 日本語の言い方。`label_in` が引く（§9.4） |
| `detect` | 必須（1〜3） | YOLOE に渡す英語（例：trash can）。1 つの種類の言葉で見つかった物は、その種類になる。Claude には見せない。Claude の英語の別名も兼ねる（O9） |
| `en` | 任意（0〜5） | Claude の英語の別名で、検出の言葉にしないもの（例：couch、trash bin、houseplant）（O4） |
| `size` | 必須 | ふつうの足跡 [長い辺, 短い辺] m。LiDAR か検出器が測るまでに使う（向きは知らないので §10.9 の決まりで使う） |
| `height` | 必須 | 高さ m。偽の LiDAR、置く高さ、検出器の空きの判定と oracle（O4） |
| `not_words`（上の段） | 任意 | 言い方を含むが、その種類ではない言葉（長椅子・車椅子・テレビ番組）。引く前に除く |
| `detect_ignore`（上の段） | 任意 | 検出器が見つけても捨てる英語（person・dog・cat。D1） |

### 7.3 読み込みで確かめること（1 つでも外れたら起動しない）

1. `version` は 1。上の段・種類の中に知らない項目があれば誤り（`word` のような打ち間違いを捕まえる）。
2. `label`：D2 の形（区切り 1〜4 個、各区切りは英小文字で始まり英小文字・数字が続く、`_` でつなぐ）、24 字まで、最初の区切りは `cw` でも `sim` でもない。どの区切りも予約語でない：`near`・`around`・`cw`・`to`・`last`・`true`・`false`・`end`、`world.ACTION_NAMES` と `PROPOSITIONS` の言葉（stand・sit・hello・dance・forward・back など）（O5）。種類の間で重ならない。`box` と `chair` がある。
3. `ja`：かな・漢字・ー・々だけ、1〜12 字、種類の間で重ならない、その種類の `words` の 1 つ。かっこ（「」（））・改行・制御文字は入らない（形で決まる）。
4. `words`：かな・漢字・ー・々だけ（v1 はラテン文字・数字・空白なし）、20 字まで、種類の中でも種類の間でも重ならない、`not_words` でない。1 字の言葉は許したものだけ（v1 では 箱・棚・机・籠・鞄）。本・人・台・個・枚・匹・冊・杯・回・階・前・後・左・右・上・下・横・中・物 は使わない。
5. 自分に戻る：§9.4 の `label_in` で、どの言葉も、それだけでも、後に「まで」「の周り」「のところ」「を」「に」が付いても、自分の種類になる（別の種類の言葉を含む言葉を捕まえる）。
6. 予約の言い回しは、どの種類にもならない。テストに置いた約 100 の一覧：動作と姿勢（ダンス・バックして など）、向き（前・右前）、障害物・物、場所（キッチン・台所・階段・2階・1号室）、数え方（1本・2台・1袋）、まとめた言葉（家具・家電・もの・何か）、あれ・それ、`design-vocabulary.md` §2.4 と `design-language.md` §7 の言い回し。
7. どの言葉も、物を扱う動詞として読まれない（`translator._handles_object(言葉)` が偽）。
8. `detect`：小文字の ASCII・空白・`-`、40 字まで、種類の間で重ならない、`detect_ignore` と重ならない。
9. `en`：`detect` と同じ形。label（`_` を空白にしたもの）・`detect`・ほかの種類の `en` と重ならない。
10. `size`：2 つの数、どちらも 0 より大きく 3.0 以下、長い辺が先。`height`：0 より大きく 3.0 以下。
11. `not_words`：どれも、ある種類の言葉を含み、それ自身は言葉でない。
12. 数：種類は 200 まで。`detect` の合計が 100 を超えたら警告（検出器は 63 で測った【仮】）。
13. 試験・例・Gazebo の部屋が使う種類がある：box・chair・table・shelf・refrigerator・trash_can・potted_plant・sofa・lamp。

テスト（`tests/test_vocabulary.py`）：入れたファイルが読める。決まりごとに、1 か所だけ壊した写しが読み込みで断られる。

## 8. id と命題

- **label：** D2 の形（§7.3 の 2）。
- **id：** `<label>_<n>`、n は 1〜99（先頭に 0 を付けない）。`ID_RE` は D2 の形の label と番号の組み合わせで fullmatch し、さらに label が `LABELS` にあることを確かめる。`sim_box_1` は形には合うが、`sim` は label にないので通らない（画面のボタンで置く箱）。
- **命題：** `near_<id>`、`around_<id>`、`around_cw_<id>`。`PROP_RE` は `(near|around_cw|around)_(<id>)` で fullmatch（今の順）。`around_cw_box_1` は `around_cw` と `box_1` に分かれる。label の最初の区切りに `cw` がないので、`around_` と `cw_…` の読み違いは起きない。
- **確かめた（code-map §6.2）：** `near_potted_plant_1`、`around_cw_potted_plant_12` は正しく分かれる。`near_box_1_2`・`near_box_01` は断る。flloat 0.3.0 は `F near_potted_plant_1`・`F around_cw_dining_table_12` を読める（命題は小文字だけ）。固定の前置き（`near_` など）があるので、flloat の言葉（last・end・true・false）と重ならない。いちばん長い命題は `around_cw_fire_extinguisher_99`（30 字）。式の長さの上限 1500 字には余る。
- **イベントの名前：** `world.event_name` のまま。物の命題は前置きと番号で終わるので、つないでも重ならない。テストで、種類の組 1081 の命題の組でイベントの名前が重ならないことを確かめる。
- **並べ方：** id は (label, 番号の数) で並べる（`objects._id_key`。box_2 が box_10 の前）。`ObjectMemory` と偽のカメラもこれを使う（今は文字の順）。
- **id を付けるのは：** logical と偽の Go2 では配置ファイルの id（Gazebo のモデル名と同じ）。detector では検出器の種類ごとの数え上げ（§11.7）。番号は 1 つの回の中で使い回さない。
- **行の確かめ（R21 のまま、1 か所）：** `objects.parse` / `parse_rows` で、`frame` が `odom`、id が §8 の形で label が `LABELS` にあり id の前半と同じ、x・y が有限、`size` が (0, 3.0] の 2 つ、`visible` が真偽、`seen` が数。新しい任意の項目は §11.8。
- **Obj：** `Obj.name` はいつも名前を返す（単語帳の `ja`。ないときは label の `_` を空白にしたもの）。`LABEL_JA[label]` で止まらない。
- `check()` は今までどおり `PROPOSITIONS` に、その Scene の載せた物の命題（§9.1）を足して確かめる。

## 9. 言葉（プロンプト・返事・メッセージ・画面）

`design-language.md` を、O1〜O3・O6〜O10 に合わせて使う。実際の Claude ではまだ流していない（§13.2 で流す）。

### 9.1 物の一覧の載せ方

- 載せるのは 8 個まで（`MAX_PROMPT_OBJECTS` のまま）。**指示の中で単語帳の言葉で言われた種類の物を先に**、近い順に 8 個まで取り、残りを近い物で埋める（O6）。並びは今と同じく近い順（位置がなければ id の順）。言われた種類がなければ、今の `listed()` とまったく同じ。
- 言われた種類（focus）は `labels_in(指示)` で、翻訳のはじめに 1 回求め、プロンプト・`check` の命題・メッセージの数え方の 3 つに同じものを渡す。Scene は凍結したまま（R2・R20）。マスを塞ぐのは、今までどおり Scene のすべての物。
- 単語帳の言葉が別の意味で当たっても、載せる物の順が変わるだけで、式や PLANT は変わらない。
- 1 行の形は今のまま：`- <id>（<ja>）：<向き> <距離> m`、見えていない物には「（いまは見えていません）」。言い方・大きさ・確からしさ・出どころは載せない。名前は単語帳の `ja` だけ（検出器の文字は入らない。R21）。
- `## Vocabulary` の物ごとの 3 行も今の形のまま（例：`near_potted_plant_1: potted_plant_1（観葉植物）の手前のマスにいて、観葉植物の方を向いている`）。今の形で一周 10/10・手前 10/10 だったので、変えない。

### 9.2 プロンプトの変わる所

- **Goal の 1 文：** 「答えは JSON で、formula（式の文字列。翻訳できないときは null）、unsupported（表せなかった部分の一覧）、substitutions（言われた言葉と違う形にした部分の一覧）、unresolved_objects（Objects の 1 つに決められなかった物の名前。ふつうは []）を返します。」
- **聞き直し：** 「直した答え（formula・unsupported・substitutions・unresolved_objects のすべて）を返してください。」
- **`### 物`** に 2 行足し、1 行を替える（ほかは今の文のまま。障害物の行は最後のまま）：
  - 足す：「同じ物の別の言い方（いす・チェア など）はその物ですが、違う種類の物（棚と冷蔵庫 など）にはしません。「近いほうの椅子」「奥の箱」のように言われたら、Objects の距離で選びます。」
  - 足す：「「家具」「家電」のように種類をまとめた言葉は、当てはまる物が Objects にちょうど 1 つのときだけその物にして、substitutions に {"said": "家具", "as": "椅子（〈id〉）"} のように入れます。そうでなければ unsupported だけに入れます（unresolved_objects には入れません）。「あれ」「それ」も unsupported です。」
  - 替える：「当てはまる物が Objects にないとき、2 つ以上あって決められないときは、その物の名前（例：箱）を unsupported に入れ、unresolved_objects にも {"said": 指示の中の物の名前, "label": 物の種類の英語（小文字の単数形。2 語以上なら _ でつなぐ。例：box、potted_plant）} を入れて、formula を null にします。unresolved_objects に入れるのはこのときだけで、ほかは [] です。」
- **`### 断るもの`** は 1 字も変えない（「物の一覧（Objects）にない…物」で、ボール・机が単語帳の種類になっても断るのは同じ。メッセージだけがコードで変わる）。
- **例：** `EXAMPLE_SCENE` に `potted_plant_9`（左前 2.1 m）を足す（box_9 前 2.0 m・chair_9 右前 2.5 m はそのまま）。物の例は 4 つの鍵を全部書き、成功の例では `"unresolved_objects": []`。足す例は「観葉植物の前まで行って」→ `F near_potted_plant_9`、「箱を押して」→ 断る（unsupported 「箱を押す」、欄は []）。「机まで行って」は欄に `{"said": "机", "label": "desk"}`（desk は table の検出の言葉なので、コードが table にする。O9）。一般の 30 の例は 3 つの鍵のまま（テストの固定を保つ）。文は `design-language.md` §2.4 のとおり。
- **返事の形（schema）：** `unresolved_objects` は `{said, label}`（どちらも文字列）の並び。4 つの鍵はどれも必須（Codex の strict schema のため）。Claude の CLI には `--json-schema`、Codex には `--output-schema` で渡す。本当の返事に鍵がなければ LLMError（「LLM の返事が読めませんでした」）。FakeLLM の返事は確かめないので、鍵がなければ [] として読む（今のテストはそのまま）。

### 9.3 返事の欄 `unresolved_objects` の確かめ

- 並びでなければ []。はじめの 10 個だけ見る。`said` と `label` が文字列の辞書だけ残す。形が悪いものは捨て、聞き直しはしない。
- `said`：後ろのかっこの注を切り、空でなく、指示の言葉の中にあるもの（`_plain` で比べる）だけ残す。例を写しただけの「机」や、利用者の言葉でないものは捨てる。
- `label`：64 字を超えたら無し。そうでなければ `vocabulary.lookup(label)`（§9.4）で単語帳の label にする（無しのこともある）。Claude の書いた英語は、どこにも出さない。
- **欄が 1 つでも残れば、式があっても断る**（O8）。何も言わずに捨てて動くことをしない。

### 9.4 種類の決め方

- **`label_in(文)`（O1）：** 単語帳のすべての言い方を、長い順に 1 つのパターンにまとめ（今の言葉の境目の決まり `word_start` / `word_end` で囲む）、NFKC にした文を前から重ならないように探す。同じ所では長い言葉が勝つ。**最後に当たった言葉の種類**を返す（日本語の名詞句は後ろが中心：「椅子の上の箱」は箱）。`not_words` は先に除く。カタカナの後ろの「ー」（チェアー）は言葉に含めて当てる。
  - これで「ゴミ箱」は trash_can（箱ではない）、「丸椅子」は stool、「本棚」は shelf になる。今の「表の順で最初に当たった種類」では、ゴミ箱が box になる。
  - 今のテストの固定のうち、「ボックス・椅子」は box から chair に変わる。
- **`labels_in(文)`：** 当たったすべての種類（§9.1 の focus）。
- **`vocabulary.lookup(英語)`（O9）：** NFKC・小文字・前後の空白を除き、空白と `-` の続きを `_` にする。label そのものならそれ。違えば、`detect` と `en`（同じように直したもの）の別名から引く。なければ後ろの s / es を 1 回だけ外して引き直す。なければ無し。例外は出さない。返すのはいつも単語帳の label。
- **断った項目ごとの種類**（1 つの決まり）：
  - その項目に含まれる欄の `said` があれば、`said` ごとに `label_in(said)`、それが無しなら Claude の label。
  - 欄がなければ（FakeLLM、古い返事、Claude が欄を空にした）`label_in(項目)`。
  - どの項目にも含まれない欄の `said` は、それ自身を項目として `unsupported` に足す（画面と試みの記録に出る）。
- 単語帳の言葉が先：人が確かめた決まった答えで、利用者の言葉のとおりの種類になる。Claude の label は、単語帳にない言い方（グリーン など）のときの予備。

### 9.5 物を扱う言葉

- 物を扱う動詞（持・押・運・拾・動か・どけ・どか と、ひらがなの形）は今までどおりコードで決める（Claude に任せない）。
- 足すこと：項目（か `said`）を指示の中で探し、そこから次の「、。,.，．！!？?」までの節に、物を扱う動詞があるかを見る。Claude が「箱」とだけ書いても、「箱を持って」は箱がいくつあっても単語帳のメッセージのまま。「箱まで行って、椅子を押して」は「「箱」が見つかりません…」と「「椅子を押す」は単語帳にない…」。
- 限り：区切りのない「椅子まで行って箱を持って」では、椅子も扱うと読まれる。変わるのはメッセージの文だけ。

### 9.6 メッセージ

メッセージは今までどおり `voice_ltl/objects.py` にまとめる（P3）。断る返事にだけ付く（動きは変えない）。断った項目の種類ごとに 1 回だけ言う（R16）。数えるのは Scene 全体（P6 のとおり。今のコードは載せた 8 個だけを数えていた）。

| Scene のその種類 | 載せた中（focus つき） | どれも凍結した位置から 6 m より遠い | メッセージ |
|---|---|---|---|
| 0 個 | — | — | 見つかりません |
| 1 個以上 | どれでも | はい（位置が要る） | 遠すぎます |
| 1 個以上 | 2 個以上 | いいえ | 決められません（数は Scene の本当の数） |
| 1 個以上 | 0 個 | いいえ | 選べません（新しい。O7） |
| 1 個以上 | 1 個 | いいえ | なし（今までどおり単語帳のメッセージ） |

種類の名前のない項目は、今までどおり単語帳のメッセージ。

文（`〈名前〉` は、利用者の言葉に当たった単語帳の言葉。当たった言葉がなければ `ja`。O3）：
- 見つかりません（文を変える）：「「〈名前〉」が見つかりません。Go2 の前に置くか、Go2 をそちらに向けてから、もう一度言ってください。」（ソファや冷蔵庫を「前に置く」のはおかしいので、向きを変える案を足す。カメラは前の 120° だけを見て、Scene は見た物を覚えている）
- 決められません（向きの案を本当の向きにする）：
  - 載せた候補の向きの言葉がすべて違い、3 つまでなら：「「箱」が 2 つあるので、どれか決められません。「左前の箱」「右前の箱」のように言ってください。」
  - 候補がちょうど 2 つで向きの言葉が同じなら：「「箱」が 2 つあるので、どれか決められません。「近いほうの箱」「遠いほうの箱」のように言ってください。」
  - ほか（今の案）：「「箱」が 4 つあるので、どれか決められません。「左の箱」のように言ってください。」
  - 数は 9 までは「N つ」、10 からは「N 個」。向きの言葉は、新しい `objects.direction(物, 位置)`（`where()` もこれを使う）で、凍結した位置から、載せた順に。
- 遠すぎます（そのまま）：「「〈名前〉」が遠すぎます（6 m まで）。」
- 選べません（新しい。O7）：「「〈名前〉」はほかの物より遠いので、選べません（近い順に 8 個まで）。」
- マス目の大きさのメッセージ（新しい 2 つ。§10.6。名前は `ja`）：「「〈名前〉」は大きすぎて、周りを回る計画が作れません。」「「〈名前〉」は大きいので、ここからは計画できません。近づいてから、もう一度言ってください。」
- そのまま：「「…」は単語帳にないので、まだできません。」、数のメッセージ、「物どうしが離れすぎていて、一度には計画できません」、「Go2 の位置がわからないので、物を使う指示はできません」、「位置がずれたので止めました。」、「この指示は満たせません（物のまわりに通れる道がありません）」。

### 9.7 画面

## 10. 大きい物の「手前」と「周回」（D6）

`design-near.md` のとおり（案 Q）。`grid.py` の部品を写して直した `grid_world_new` を、今の `grid.grid_world` と並べて app の container で流して確かめてある。

### 10.1 今の決まりが大きい物で働かないわけ

今は、物の半径 r（外接円。r = hypot(sx, sy) / 2）で、塞ぐのは中心から r + 0.45 m 以内、手前の帯は中心から r + 0.75 m〜min(r + 1.5, 1.3) m（向きの差 40° 以内）。
- 手前の帯の幅は 0.55 − r なので、r > 0.55 m（0.78 m 角より大きい物）で空になる。格子に合った物なら 0.55 m 角で、もう空。
- 箱でも危うい：Gazebo で測った箱（0.523 × 0.529、r 0.372）は、Go2 が格子にぴったり立つと手前のマスが 0（`gazebo_objects_e2e.md` 第 4 部）。
- 円で塞ぐと、細長い物の長い辺の横がつぶれる。2.0 × 0.9 のソファは中心から 1.55 m まで、長い辺から 1.1 m まで塞ぐ。

### 10.2 塞ぐマス

距離はすべて odom で測る（`size` は odom の x・y の長さなので）。物の中心 (x_o, y_o)、a = sx/2、b = sy/2、マスの中心 p について：
- d_c：中心までの距離（今と同じ）。
- d_e：**足跡（`size` の四角）までの距離**（中は 0。`objects.edge_distance` と同じ）。

**マスは d_e ≤ 0.45 m（`BLOCK_MARGIN`、+EPS）なら塞ぐ。** 0.45 の値はそのまま（R5 の、格子から外れたときのいちばん悪い縁からの間と同じ）。Scene のすべての物が塞ぐ（R7）、Go2 が始めるマスは塞がない（今と同じ）。
- 既定の箱と椅子は、今と同じ 9 マスずつを塞ぐ（既定の 5 つの式で同じ）。
- 空いたマスどうしの 1 歩は、どの足跡からも √(0.45² − 0.25²) = 0.374 m 以上離れる。
- d_e ≥ d_c − r がいつも成り立つので、新しく塞ぐマスは今も塞いでいる。空きのマスは今の空きを含む。

### 10.3 手前のマス（R4 を置き換える）

- **背骨（spine）：** 中心を通り、長い辺の向きに伸びる線分（半分の長さ |a − b|）。正方形なら中心の 1 点。s(p) は p にいちばん近い背骨の点。
- **芯までの距離 d_k：** |p − s(p)| − min(a, b)（足跡の中のいちばん大きい「角の丸い四角」までの距離）。長い辺の横では d_k = d_e、正方形では d_k = d_c − a。
- (マス c、向き h) は、c が空いていて、**A か B** なら、その物の手前：
  - **帯 A（今のまま）：** r + 0.75 ≤ d_c ≤ min(r + 1.5, 1.3)、中心の方向と向きの差 ≤ 40°。
  - **帯 B（新しい）：** d_e ≥ **0.575**、d_c ≥ **1.05**、d_k ≤ **1.075**、**いちばん近い背骨の点**の方向と向きの差 ≤ 40°。
- B の向きの決まりは、正方形なら今の中心の決まりと同じ。長い辺の横では辺にまっすぐ向く。背骨の端より先では、その端を向く。1 つの帯の中で、1 つのマスに向きが 2 つになることはない。

| 定数 | 値 | わけ |
|---|---|---|
| `BLOCK_MARGIN` | 0.45（足跡から測る） | Go2 がその場で回っても当たらない幅（今と同じ値） |
| `NEAR_MIN_MARGIN`・`NEAR_MAX_MARGIN`・`NEAR_MAX_DISTANCE`・`NEAR_MAX_ANGLE_DEG` | 0.75・1.5・1.3・40（帯 A、そのまま） | 既定の置き方と小さい物は今のまま（N1） |
| `NEAR_MAX_CORE`（新しい） | 1.075 | = 1.3 − 0.225。正方形（半辺 h）では B は d_c ≤ h + 1.075。0.45 m の椅子でちょうど N1 の 1.3 m。長い辺の横では縁から 1.075 m まで |
| `NEAR_MIN_EDGE`（新しい） | 0.575 | = 1.075 − 0.5。長い辺の横で B がちょうど 1 マスの深さになる。止まるときのずれ 0.15 m があっても、胴の中心は縁から 0.425 m 以上（鼻先 0.35 m は当たらない） |
| `NEAR_MIN_CENTRE`（新しい） | 1.05 | 既定の 8 マス（1.118 m）を残し、軸の上の 4 マス（1.0 m）を入れない幅 (1.0, 1.118] の真ん中。r + 0.75 にしないのは、0.64〜0.85 m 角の物（冷蔵庫・事務いす）が格子のすき間に落ちるため。短い辺の半分が 0.475 m 以上の物では効かない |

案 P（0.6 / 1.1）も同じくらい強いが、椅子の計画が 1.325 m まで行き、§2 の「計画は 1.3 m の内側」が変わる。D6 は §2 を変えないので、案 Q にした（O11）。

### 10.4 範囲（R8）

指示に出る物ごとに、マス目の x・y の向きの半分の長さを取り、Go2 のマスと 1 マスの余白を足す（今と同じ）。面積は 256 マスまで。
- 手前：max(min(r + 1.5, 1.3), 芯の箱)。芯の箱は、背骨の向きに |a − b|·|cos ψ| + min(a, b) + 1.075、横に |a − b|·|sin ψ| + min(a, b) + 1.075（ψ は背骨とマス目の軸の角度）。
- 周回：r + 1.75（今と同じ）。

- **空のときに 1 回だけ広げる（O15）：** 監督器が空で、式の物の命題のどれかが行けるどの状態にもないとき（R15 の場合）、余白を 3 マスにして 1 回だけ作り直す（面積が 256 を超えるなら作り直さない）。それでも空なら R15 のメッセージ。家具の多い部屋で、1 マスの余白では回り道ができないため（試しの家具の並びで、ソファ・棚・事務いすは手前のマスがあるのに、自分の長方形の中に道がなかった【仮】）。

### 10.9 足跡が本当の物より小さくならないこと（前提。O12）

ここまでの決まりは、`size` が本当の物を覆うことを前提にしている。今は崩れうる：
- 橋渡しは、物の中心から `SIZE_RADIUS` = 0.6 m 以内の点だけで大きさを測る。2.0 m のソファは約 1.2 m として送られ、塞ぐマスと手前のマスが本当のソファの中に入る（止めるのは LiDAR の前の物のビットだけ）。
- 単語帳の `size` には向きがない。

決めたこと：
- **測る半径は種類ごと：** max(0.6, 単語帳の `size` の対角の半分 + 0.3) m。箱と椅子では 0.654 m・0.618 m で、まわりにほかの物の点はないので、測る値は変わらない（§13.6 で確かめる）。
- **測るまでの足跡は、単語帳の長い辺の正方形 [L, L]**（向きを知らないので、どの向きでもほぼ覆う）で、`measured: false`。箱と椅子は正方形なので今と同じ。椅子の既定は 0.5 から 0.45 になる（LiDAR が測るまで。Gazebo では、止まっている間にすぐ測る）。
- 橋渡し（logical）：はじめて測ったら置き換え、その後は軸ごとに大きいほうを残す（今と同じ）。
- 検出器：1 つの見え方から足跡を作るとき、見えない奥行きを単語帳の大きさで補う（§11.6）。測った値と単語帳の値の軸ごとの大きいほうにはしない（向きのある物が 1.8 × 1.8 に膨らむため）。点が少ないときの予備は [L, L]、`measured: false`。
- 物の向き（yaw）は送らない（O13）。30° 回ったソファは 2.18 × 1.78 として送られる。計画は安全なまま、手前のマスが本当の縁から最大約 0.4 m 遠くなる。部屋の家具は、長い辺を世界の軸に合わせて置く（§12）。

**前の物のビット（O14）：** 帯 B のいちばん内側（縁から 0.575 m）に着くと、止まった後の惰性 0.10〜0.15 m で `obstacle_front`（胴の中心から前 0.5 m で「あり」）が立つことがある。目標にはもう着いているので、そのまま受ける（続く「前に進んで」は待つ。ソファが前にあるのでそれが正しい）。箱と椅子の帯 B のマスは縁から 0.73 m 以上で起きない。Gazebo のソファの手前で 1 回確かめ、困るなら、短い辺の半分が 0.45 m 以上の物だけ `NEAR_MIN_EDGE` を 0.65 にする（1 マスの深さの保証は失う）。

### 11.5 いつ検出するか

- `StillGate`（今の数：どの軸も角速度 0.1 rad/s 以下、速さ 0.05 m/s 以下が 0.3 秒以上）が開いている間に来た絵と LiDAR のスキャンを、**来たときの「止まり始め」の時刻と一緒に**取っておく。開いていないときのものは捨てる（数える）。
- 同じ止まりの間に取った、いちばん新しい絵とスキャンを組にする。odometry が両方の時刻を過ぎるまで（0.1 秒まで）待つ。2 つの時刻の位置が 0.02 m か 1° より違えば捨てる。
- 推論は 1 つずつ（1 つの受け口、新しい仕事が勝つ）。推論の終わりから次の始まりまで 1.0 秒以上（`DET_MIN_GAP_S`）。1 つの止まりの中で 3 回推論したら、その止まりが終わるまで 3.0 秒ごと（`DET_IDLE_PERIOD_S`。見えている印を新しく保ち、止まっている間に置かれた箱も拾う）。歩いている間は推論しない（絵は来るが捨てる）。
- 伏せ・座り・StopMove の後の立ちは止まっているとみなす。伏せたときの視点（カメラが床から約 0.15 m。試しの絵は立って 0.39 m）での検出は測っていない。
- 止まってから一覧に出るまでの見込み：約 3.5 秒【仮】（0.3 秒 + 次の絵まで 0.5 秒 + 推論 0.45 秒 + 1.0 秒 + 0.45 秒 + 次の 2 Hz まで 0.5 秒）。この間に言われた指示は、まだ出ていない物を使えない（凍結。今と同じ決まり）。
- 止まっている間の負荷：はじめの 3 回は 1 スレッドの約 31 %、その後は約 13 %。

### 11.6 位置と大きさ（LiDAR を絵に写す）

numpy だけで書く（`detector/camera.py`・`detector/geometry.py`）。app のイメージ（numpy 1.26、cv2 なし）でも検出器のイメージ（numpy 2.x）でもテストが流れる。
- **座標：** Gazebo のカメラの体の向きは x 前・y 左・z 上（ROS の光学の向きではない）。内部の数は CameraInfo の K、来るまでは画角から fx = fy = (W/2) / tan(hfov/2)、cx = W/2、cy = H/2（640 で 184.836。試しの K と同じ。1 % より違えば警告）。写すのは u = cx − fx·y/x、v = cy − fy·z/x（x > 0.1 m の点だけ）。LiDAR からカメラへは平行移動だけ（`LIDAR_IN_BODY` − `CAMERA_IN_BODY` = (−0.04715, 0.00003, 0.05703)）で、4 × 4 の変換として持つ（実機 B の逆さまの L1 は自分の変換を渡せる）。世界の点は、スキャンの時刻の位置で `bridge_core.lidar_points_world` を使う（傾きも直る）。試しの記録の box_1 の点が、記録の画素に写ることを確かめる。
- **1 つの検出の点：** 世界の高さ 0.05〜2.5 m の点を写し、絵の外と後ろを捨てる。検出のマスク（2 px 縮めたもの）の中の点、マスクがなければ枠を幅 10 %・高さ 5 % 縮めた中の点を取る。odom の XY で単連結のかたまりにする（0.25 m）。点の数が max(5, いちばん大きいかたまりの 25 %) 以上のかたまりのうち、いちばん近い点がカメラにいちばん近いものを取る（奥の背景は距離で、手前の細い隠れは大きさで負ける。試しでは枠の中の点の中央値が、物の原点から 0.6〜3.2 m ずれた枠があった【仮】）。
- **1 つの見え方からの足跡：** 中央値から 3·MAD + 0.1 m より離れた点を除く。カメラからかたまりの中央値への向き（r̂）と横の向き（t̂）で、手前 near、見えた奥行き d_obs、見えた幅 w_obs を測る。d_obs ≥ 0.6·S なら奥行きは見えた値。そうでなければ見えない奥を補う：w_obs < 0.7·L なら L（短い辺を見ている）、そうでなければ S、そして d = max(d, d_obs)。幅は max(w_obs, 0.1)。その四角の 4 隅を odom にして、軸に沿った四角（中心と [sx, sy]）にし、各辺を [0.1, 3.0] に収める。max(sx, sy) > 2·L + 0.5 なら、まわりとくっついたとみなし、見えた印（名前と確からしさ）だけ数えて形は使わない。L・S は単語帳の長い辺・短い辺。
- **見え方を合わせる：** 追跡ごとに、LiDAR に支えられた直近 6 回の当たりの点（0.05 m で間引き、2000 点まで）を持ち、その全部で上の足跡を作る。1 回の悪い枠は 6 回で抜けるので、大きさは小さくも戻れる（橋渡しの「軸ごとの大きいほうをずっと」とは違う）。
- **点が少ないときの予備：** 枠の下の真ん中の画素を通る線を床（z = 0）に当てる。枠の下が絵の下の端から 3 px 以上上にあり、水平線より下で、8 m 以内のときだけ。そこから S/2 奥を位置にし、大きさは [L, L]、`measured: false`（O12）。立って 3 m で 1 px あたり約 0.125 m、伏せると約 0.32 m 粗いので、予備の見え方は LiDAR に支えられた追跡を動かさない。

### 11.7 追跡・id・忘れ方（`detector/tracker.py`）

- **見え方：** 単語帳の種類で、確からしさ 0.25 以上（`CONF_MIN`。推論は 0.10 まで返す）。`detect_ignore`（人・動物）の検出は追跡に入らない。同じ絵の場所の違う名前の重なりは、検出器の種類を区別しない NMS（IoU 0.7）で先に除く。
- **結び付け（1 つの絵ごと、中心の距離が近い順に 1 対 1）：** まず同じ種類で、中心の距離が 0.5 + 0.5·max(r) m 以内（予備の見え方は +0.5）。次に、結び付かなかった見え方の足跡が、結び付かなかった別の種類の追跡と IoU 0.4 以上なら、その追跡への「名前の票」にする（形と見えた印は更新し、確からしさをその名前に足す。試しの段ボール箱が box と bench に揺れた形【仮】）。ほかは新しい仮の追跡。
- **確かめ：** 仮の追跡は、その場所がカメラの中に入った直近 3 回の止まった絵のうち 2 回当たり（0.5 秒以上離れて）、そのうち 1 回以上が LiDAR に支えられていれば、確かな追跡になる。LiDAR に支えられた当たりがないときは、3 回中 3 回、確からしさ 0.5 以上。30 秒で確かにならなければ、id を持たないまま捨てる。止まりの中の絵はほとんど同じ絵なので、何もない所に出る幻を防ぐのは、回数より LiDAR の支えと空きの判定。
- **id：** 確かになったときに名前を決め、`<label>_<n>`、n は種類ごとの数え上げ（1 から）。**1 つの検出器の回の中で使い回さない、n ≤ 99（D2）。** 99 を超えたら、その種類の新しい追跡は出さず、警告を 1 回記録する。検出器を起動し直すと 1 から（走っている計画は凍結した Scene の位置を使うので困らない）。
- **名前の付け直し：** 直近 5 回の当たりで、別の名前の確からしさの合計が今の名前の 2 倍以上なら、今の id を終わりにし（二度と使わない）、新しい名前の新しい id にする。出した名前が変わるのはこのときだけ。
- **まとめ：** 確かな追跡 2 つの足跡が IoU 0.5 以上か、片方の中心がもう片方の足跡の中にあれば、古い id にまとめる。少し重なるだけの違う種類（机の下の椅子）は 2 つのまま。
- **出す項目：** x・y・size（上の足跡か予備）、`confidence`（その名前の直近 10 回の当たりの中央値、小数 3 けた）、`measured`（LiDAR に支えられた当たりがあれば真）、`seen`（最後の当たりの絵が来た `time.time()`）、`visible`（5 秒以内に当たり。歩いている間は推論しないので、5 秒で「見えていない」になり、プロンプトの「（いまは見えていません）」が本当になる）。並びは `_id_key`。
- **忘れ方（橋渡しは忘れない。検出器は忘れる）：** **LiDAR に支えられた確かな追跡は、その場所が空だという形の証拠があるときだけ消す。見落としだけでは消さない**（1 つの絵で見つかるのは物の 30〜60 % だった【仮】。見落としで消すと、本当の物が数分ごとに番号を変え、99 を使い切る）。
  - 空きの判定（LiDAR の組がある止まった絵ごと）：足跡を 0.1 m 広げ、高さ h（単語帳の高さ、0.3 m 以上）の箱の中の点 n_in と、足跡の奥の向こうに当たり、足跡の距離で箱の高さの中を通った線の数 n_through を数える。n_in < 3 かつ n_through ≥ 5 なら空。隠れた場所は線が手前で止まるので空にならない。
  - 0.5 秒以上離れた 2 回が空なら消す。消した id は使い回さない。
  - LiDAR に支えのない確かな追跡は、隠れていない見える絵で 3 回続けて当たらなければ消す。
  - カメラの外の物は、`visible: false` でずっと覚えている（止まった部屋。R20 と同じ考え）。
  - つまり、本当の形の上の間違い（名前だけ違う）は残り、何もない所の幻・どけた箱・動かした物は、次にその場所を止まって見たときに消える。

### 11.8 送る形

```json
{"frame": "odom", "stamp": 1793938821.82, "source": "detector",
 "objects": [{"id": "chair_1", "label": "chair", "x": 1.749, "y": 0.719, "size": [0.42, 0.40],
              "seen": 1793938821.4, "visible": true, "confidence": 0.81, "measured": true}]}
```

- メッセージの `source`（任意）：`logical`・`detector`・`fake` のどれか。橋渡しは `logical`（どちらのトピックも）、偽の Go2 は `fake`、検出器は `detector`。ほかの値ならメッセージをまるごと捨てる（R21 と同じ厳しさ）。ないときは不明（古い送り手）。
- 行の `confidence`（任意、[0, 1] の有限の数、真偽は不可）と `measured`（任意、真偽）。悪い値なら、悪い `size` と同じく行を捨てる。知らない鍵は今までどおり無視。
- `Obj` は `confidence`・`measured` を持つ（既定は無し）。`Obj.to_row()` は、値があるときだけ書く。だから論理カメラと偽の Go2 の行は今とバイト単位で同じで、RosLink（`to_row()` で書き直す）も新しい項目を落とさない。`objects.parse_source(payload)` が `source` を読む 1 か所。`format_message(objs, stamp, source=None)`。`RosLink.objects_source()`（古ければ無し）。
- 日本語の名前は送らない。app が単語帳から付ける（検出器の文字はプロンプトに入らない）。`source`・`confidence`・`measured` はプロンプトに入れない。
- 変えないもの：`frame: odom`、2 Hz、2 秒で古い（`OBJECTS_STALE_S`）、`seen` は送り手の時計、`time.time()` の時刻。検出器は起動したときから、物がなくても 2 Hz で出す（2 秒の沈黙は「検出器がいない」の意味になる）。

### 11.9 壊れたとき

| 何が | 検出器 | app から見えること |
|---|---|---|
| 検出器の container が動いていない（detector のとき） | — | 2 秒で一覧が空。物の指示は「見つかりません」。ほかの指示と LiDAR の止まりは変わらない |
| モデルが読めない・重みがない | 記録して 0 でない値で終わる → compose が 3 回まで起動し直す | 同じ |
| 10 秒カメラの絵が来ない | 追跡を残し、2 Hz で出し続ける（5 秒で見えていないになる）。状態 `no_camera`、1 分に 1 回警告 | 覚えた物、見えている物なし |
| 止まりの間に LiDAR が来ない・odometry がない | 絵を捨てる（形も印もなし）。状態 `no_cloud` / `no_odometry` | 同じ |
| 推論で例外 | 記録して数える。3 回続けば 30 秒休んでやり直す。追跡と出すのは続ける。状態 `detector_error` | 覚えた物 |

`/go2/detector_status`（1 Hz）：ok、reason、絵とスキャンの古さ、止まっているか、推論の時間の中央値、推論の数（全部と今の止まりの中）、仮と確かな追跡の数。

### 11.10 検出器の取り替え口（`detector/protocol.py`）

- `Detection`：label（単語帳の label。取り替え口の中で検出器の名前を写す）、confidence（[0, 1]）、box（絵の画素で x0 < x1、y0 < y1）、mask（任意、絵と同じ大きさの真偽）。
- `Detector`：name（記録だけ）、`set_vocabulary(label → 英語の一覧, 捨てる英語)`、`detect(RGB の絵) -> Detection の一覧`（絵を変えない・持たない、種類を区別しない NMS をする、自分の下限まで低い確からしさを返してよい。`CONF_MIN` は core がかける）、`close()`。
- `load_detector(name)` は環境の `DETECTOR`（既定 `yoloe`）で選ぶ：
  - `detector/yoloe.py` の YOLOE：**ultralytics と torch を import する唯一のファイル**（`load_detector` が必要なときだけ import する）。すべての言葉と捨てる言葉を 1 つの種類の一覧にし（人を一覧から外すと、名前で探す検出器は人にいちばん近い種類の名前を付けるため）、NMS の後で捨てる言葉を除く。RGB → BGR、`conf=0.10`、`iou=0.7`、`agnostic_nms=True`、`imgsz=640`、マスクを絵の大きさにする、スレッド（§11.1）。
  - `detector/oracle.py`：測るためだけ（既定にしない）。正解の足跡 × 単語帳の高さを絵に写した枠を、確からしさ 1.0 で返す（隠れは考えない）。検出器の誤りと、形・追跡の誤りを分けて測れる。
  - テストの `ScriptedDetector`：決めた検出を返す。
- AGPL を避けたくなったら、この 4 つを満たす別の検出器（OWLv2・Grounding DINO など。ライセンスと CPU の速さを先に確かめる）に替える。マスクがない検出器は、枠を縮める道で動く。

### 11.11 正しさの測り方

- `objects_check.py accuracy [--seconds 15] [--range 5.0] [--target <正解の id> ...]`：`/go2/objects`（`source: "detector"` でなければ終了コード 2）、`/gazebo/objects_truth`、odometry、`/go2/detector_status` を受け、Go2 が止まっていて、その止まりで検出器が 3 回以上推論するまで待ってから比べる。
  - 純粋な関数 `accuracy(...)` にしてテストする。範囲に入る正解：見えている、Go2 から `--range` 以内、配置で `detectable`。検出の行と正解の行を、中心の距離が近い順に、max(0.75, 正解の半径) 以内で組にする（名前は別に数える）。組ごとに位置の誤り、大きさの誤り（軸ごとの差の大きいほう）、名前が正しいか（正解の `accept` の中か）。recall と、組にならない検出（誤検出）。
  - JSON 1 行、終了コード 0 合格・1 不合格・2 データなし。しきい値は §13.3。
- `run` / `summarize` に `--target <正解の id>`：その正解の足跡で手前・周回を測る（box_1・chair_1 の固定の代わり）。detector のときの式の id（検出器の id）と、測る正解の id は別に渡せる。
- **Gazebo なしで：** `gazebo/tools/record_frames.py`（検出器のイメージで動く）が、止まっている間の組を 1 つずつ保存する（絵 PNG、スキャン `.npy`、両方の時刻の位置、CameraInfo、正解、状態）。`gazebo/tools/detector_check.py` が保存した組を `DetectorCore` に `DETECTOR=yoloe|oracle` で流し、上と同じ JSON を出す。しきい値の調整（CONF_MIN、M/N、かたまりの幅、補い方）はここでする（Gazebo の測りは 1 つずつ、を守れる）。
- テストの材料は、スキャン・位置・正解の JSON（1 組約 70 KB）で、**絵は入れない**（CC BY のモデルの絵を公開のリポジトリに入れると表示が要る。形のテストは正解を写した枠で作る）。

## 18. 測りの途中の数【仮】と、測ったときの条件

- **カメラの試し**（`spike/gazebo-camera.md`、12:47〜13:43）：GUI あり、毎回 Gazebo を起動し直し、75 秒の窓。ふだんの場面の基準はバッテリーでだけ測った。家具の場面は AC。家具の場面の 640×480、人を抜いた家具の場面、AC のふだんの場面の基準は、利用者の Gazebo が 13:41 に動き出したので測っていない（base/np1 は利用者の `go2-gazebo-1` 336 % と重なり、数えない）。同じ構成で ±0.03 ほど揺れる。
- **重なり：** 手前の設計の、手元の Mac で流した純粋な Python の掃き出し（nice 10〜19、合わせて 1 コアで約 10 分）が、カメラの試しの回と重なった：13:05〜13:07（c640x2/r2・c320x5/r2）、13:16〜13:17（c640x2/r3・c320x2/r3）、13:21（trig320/r3）、13:23〜13:27（base/f1・c320x2/f1・c320x5/f1）、13:31〜13:34（c320x5/f2・base/f2）、13:36:30〜13:39（c320x2/f3）、13:40（trig320/f3）。その container の回（13:35:21〜13:36:07）は、試しの次の回を 49 秒待たせた。家具の場面の基準（base/f1・f2）も重なって高かったので、カメラの重さの結論は変わらないと見るが、数はこの重なりのある値。
- **検出器の試し**（`spike/detector.md`）：Docker の VM 8 vCPU、ほかの担当の container が出入りし、Gazebo の横の数は別の Gazebo も動いていた時のもの。絵の数（21/70 など）は試しの部屋の 6 視点、63 の言葉、立った高さ。この部屋・この単語帳・伏せた視点では測っていない。
- **マス目の数**（`design-near.md`・code-map）：時間は混んだ Mac の値（ほかの Gazebo が 347〜430 %）。手前の数え（§10.7）と PLANT の大きさは計算なので、時間以外は確か。試しの家具の並びでの手前の行（§10.4 の O15 のわけ）は、試しの 3D 枠を丸めた足跡の例で、この部屋の測りではない。
- **単語帳と部屋の確かめ**（`design-vocabulary.md`）：手元の Mac で nice 19、container は使っていない。部屋の PLANT は pitct を置き換えて作った（合成はしていない）。
- **言葉の大きさ**（`design-language.md`）：worktree のコードで `build_prompt` だけを呼んだ値（pitct と flloat は置き換え）。実際の Claude ではまだ流していない。
